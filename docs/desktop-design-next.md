# Vantry 桌面端设计规范（0.1.9）

适用范围：internal/desktop的MyGo原生界面。设计目标是安静、以文字为主、信息密度高但不拥挤的多机器、多会话与Agent工作台。本规范描述视觉、布局及交互，不改变Core/API/Provider或路由合同。

## 1. 用户反馈的问题与判断

| 现象（用户截图） | 根因 | 处理 |
| --- | --- | --- |
| 顶栏十余个同权重图标，外加“2 轮对话”文字 | 工具、会话操作、帮助、大纲平铺，没有分组 | 五个工具合成一个分段胶囊；大纲改为图标，轮数放进提示；帮助移到侧栏底部 |
| 时间线里每条工具/步骤行右端都有一个孤立的 `›` | 折叠控件的箭头常驻，并且固定在列尾 | 统一为 `disclosureRow`：箭头只在悬停或展开时出现，并保留占位，悬停时不跳动 |
| 步骤展开后像一串零散的行，左侧细线不明显 | 展开态没有容器 | 展开后的步骤组成为圆角描边面板，摘要行就是面板标题 |
| 回复里 `## 结果` 比对话本身还醒目 | 标题字号 1.6em/1.35em，按文档排版 | 对话内标题降到 1.3/1.15/1.02em，主要靠字重和间距区分 |
| 侧栏每行都重复项目名，三行卡片 64px，信息重复且占位大 | 行内项目元信息与分组标题重复 | 两行行高 50px：标题和状态/时间在上，分支、子任务和 Pi 在下；项目名只在项目分组之外显示 |
| 审批同时出现“需要你的确认”状态行、工具行和卡片 | 同一状态出现三次 | 状态只由审批卡头表达；正在运行的状态行在等待审批时不再重复 |
| “跳到最新”出现时把会话整体下推 | 按钮作为列表上方的一行占位 | 改为浮在会话区底部的胶囊，不改变布局 |
| 次要文字过淡（深色 `#5C6472`，浅色 `#94A0B4`） | 对比度约 3.3 和 2.6 | 重新设定灰阶，见下节 |

## 2. 设计令牌

### 2.1 颜色（`view.go: workbenchTheme`）

2026-11-17 更新：深色使用纯黑画布与侧栏，抬升面为#111，细线约8–11%白；灰阶中性无蓝偏，蓝色用于主操作、链接和焦点。

| 令牌 | 深色 | 浅色 | 用途 |
| --- | --- | --- | --- |
| sidebar | `#000000` | `#FAFAFA`（zinc-50） | 最低层 |
| canvas / surface | `#000000` | `#FCFCFC`（zinc-25） | 阅读区 |
| soft | `#141414` | `#F4F4F5` | 悬停填充、行内代码 |
| raised | `#111111` | `#FFFFFF` | 输入卡、弹层、审批卡、设置窗口 |
| code | `#0B0B0B` | `#F7F7F8` | 代码井 |
| ink | `#F5F5F5` | `#18181B` | 内容 |
| muted | `#A3A3A3`（neutral-400） | `#5F5F68` | 次要文字 |
| faint | `#8F8F8F`（secondary-label） | `#62626B` | 元信息 |
| line / lineSoft | `#262626` / `#1A1A1A` | `#E4E4E7` / `#EDEDF0` | 控件边线 / 结构分隔 |
| selected / rowHover | `#1C1C1C` / `#121212` | `#EBEBED` / `#F1F1F3` | 选中 / 悬停 |
| accent | `#346BF1`（oklch .571 .21 264） | `#1B4ED8`（oklch .488 .217 264） | 主操作 |

语义色只表示状态：运行中（sky）、需要处理（amber）、完成（emerald）、失败（red）。深色模式提亮为 `#34D399/#FBBF24/#F87171`，保证小字可读。浅色模式的 warning 使用 `#B45309`（5.0:1）。

### 2.2 字号与字重

| 层级 | 字号 | 字重 | 示例 |
| --- | --- | --- | --- |
| 回复正文 | 15，行高 1.65 | 400，强调 600 | Markdown |
| 用户消息 / 输入框 | 14，行高 1.5–1.55 | 400 | 气泡、草稿 |
| 标题与名称 | 13 | 500–600 | 侧栏标题、顶栏标题、子任务名 |
| 折叠标签 | 12.5 | 500（标签）/ 400（摘要） | 思考过程、N 个步骤、运行 |
| 元信息 | 11–11.5 | 400 | 分支、时间、模型、状态 |

对话、侧栏、输入区、审批和队列这些常用界面不再使用 10px 文字。Git、SSH、插件中心等工具面板仍保留原来的紧凑字号，下一轮单独处理。本轮改动涉及的中文标题由 `Bold()`（700）改为 600，避免中文显得过粗。

### 2.3 尺寸与间距

- 阅读宽度 `readingWidth = 760`：对话、输入框和新会话首页共用。
- 两轮对话间距 36，同一轮内间距 16，回复内部块间距 10。
- 圆角：行和按钮 7–8，卡片 11–12，输入卡 18，胶囊为高度的一半。
- 交互行高 28–30；侧栏两行行高 50，单行行高 34。

## 3. 组件

**图标**：使用Lucide 0.564的原始几何，由 `scripts/gen_lucide_icons.py` 生成注册表，MyGo以一致圆角描边原生绘制。品牌与系统权限图标保留明确的来源和许可，见[第三方notices](../THIRD_PARTY_NOTICES.md)。未知图标名在启动时明确报错。

**设置类页面**（`settings_kit.go`）：分区标题、圆角细线分组，每行左侧标题与说明、右侧控件，行间用细线分隔。设置窗口采用左侧分区导航与右侧单页；插件中心、远程桌面的共享开关、权限状态、中继和连接地址复用同一套件。


**顶栏**：左侧为项目徽标、项目名、`/`、标题（600）和状态胶囊；右侧依次为会话内查找、大纲图标、五个工具组成的分段胶囊、更多和工作区开关。宽度小于 760 时，工具折叠为菜单，菜单中也提供“快捷键速查”。

**时间线**
- 折叠行（`disclosureRow`）：图标 + 500 字重标签 + faint 摘要 + 尾部箭头（悬停或展开时可见），悬停背景为 soft。思考过程、步骤组和单个工具都使用同一个控件。
- 步骤组展开后显示为 `lineSoft` 描边面板；失败数量用红色单独标出，不混在摘要里。
- 工具详情是凹陷的代码井（code 背景 + lineSoft 描边），上方用 11px 小标题注明“命令”或“输出”。
- 回合信息：`已完成 · 3 分 12 秒 · 模型`，使用 faint 色；复制、引用、分叉是 26px 图标按钮。最新一轮始终可见；较早的回合在悬停或键盘焦点进入时显示，可访问名称不变。点击复制后，图标在原位变成绿色对勾并显示“已复制”，1.5 秒后恢复。
- 审批卡：raised 背景 + amber 描边；卡头“需要你的确认”、14px 标题、命令代码井，右侧依次为“拒绝”（描边）和“允许执行”（主按钮），二者都是 30px 高。
- 子任务卡：`lineSoft` 描边；运行中显示呼吸点，状态文字使用状态色；“取消”平时为 muted 色，悬停时变红。
- “跳到最新”：浮在会话区底部中间的 raised 胶囊。

**侧栏**：项目分组标题为 16px 徽标 + 名称（600）+ 数量，聊天和新建按钮只在悬停或焦点进入时出现。行标题使用 500 字重；未选中时颜色略降，选中或未读时为 ink。底部只保留一条分隔线（由“已归档”提供），底栏依次为设置、Git、用量、快捷键和外观。

**输入区**：输入卡是画布上唯一抬升的表面（raised + 阴影）。获得焦点时边线提亮，拖入文件时边线变为 accent。窗口高度小于 700 时，最小行数降为 1。底栏依次为附件、规划、模型（π + 名称 + ⌄）、思考等级和主按钮；没有内容时，发送按钮显示为中性灰底，不显示半透明的蓝色。下方的上下文条依次显示运行机器、项目与工作区、分支和权限；远端代理时显示目标机器和“远端工作区”，规则与原来相同。

## 4. 保留的行为

原生侧栏按标题首字母定位（保留 Sidebar 的真实 label，内置文字透明，避免与自绘标题重叠）、快捷键（⌘N/⌘K/⌘F/⌘//⌘,/F6/Esc）、按会话保存的草稿和阅读位置、Queue/Steer、审批响应、子任务打开/取消、侧栏拖拽（置顶、归档、移回）、悬停预览卡（450ms）、`vantry-thread://` 链接的 environmentId 路由，以及远端代理禁用本机文件/Git/终端/模型目录，全部不变；只调整呈现方式。

## 5. 主代理整合与实际启用

主代理已整合指定 Opus 5.5 的独立提交，并核对实际渲染图；另外补回原生侧栏按标题首字母定位，调整元信息在选中行背景上的对比度。最终源码的完整普通测试、全仓 vet 与相关 UI/启动/脚本工具定向 race 通过。使用新 e2e 二进制的真实 macOS 原生窗口九项冒烟通过，覆盖中文多行 setValue、流式、停止、关窗后 Core 持续、历史和未发送草稿恢复。真人中文输入法候选尚未验收，未将完整 desktop race 记为通过。

MacBook 已在备份默认数据后启用配套 0.1.9 App/Core，保留 9 个线程和 3 次运行，schema 保持 10。产物在 `dist/darwin-arm64/`；最终设计帧、原生窗口和安装记录在 本机私有工件目录。

## 6. 验收方式

- `internal/desktop/design_review_test.go`
  - `TestDesignAcceptanceAcrossWindows`：在 1440/1399/1080/640 宽和 1280×600 短窗口（深色和浅色）下，检查输入框、拒绝和允许按钮都在窗口内；审批状态只出现一次；顶栏没有“N 轮对话”文字；折叠标签不会被挤成竖排；阅读列在 760 宽度下居中。
  - `TestDesignOpenReasoningStaysInColumn`：展开后的思考内容不超出阅读列（已确认能检测出旧的 margin 溢出问题）。
  - `TestDesignQuietHistoryAndFeedback`：复制操作可以触达，原位显示确认后会过期；项目分组内的行不重复项目名。
  - `TestDesignReviewRenders`：设置 `VANTRY_DESIGN_RENDER_DIR` 后导出截图，覆盖长回复、步骤展开、审批、子任务、模型弹层、首页和悬停状态。
