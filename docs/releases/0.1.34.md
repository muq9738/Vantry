# Vantry 0.1.34

Fixes LAN direct connections to remote peers such as `Mac mini` running older Core builds, persists mDNS direct addresses for paired peers across restarts, and clarifies LAN-direct status in Settings → Environments.

- **Separate local vs. remote desktop capabilities**: Remote workbenches now validate `RequiredRemoteDesktopCapabilities()` (excluding the local-only `provider.pi.runtime.v1` capability introduced in `0.1.32`) in `ConnectEnvironment`, `--peer`, and `--remote-host`, while local Core startup continues to require `provider.pi.runtime.v1`.
- **Persist mDNS LAN direct endpoints for paired peers**: When mDNS discovers an updated LAN address for an already-paired peer, Vantry immediately persists `direct` in `remote-access.json` so direct LAN connections use the latest host IP/port without needing a relay.
- **Clear LAN-direct summaries in Settings → Environments**: Paired machines with no relay now show `仅局域网直连` / `LAN direct only` alongside their discovered LAN `ip:port`.

Release packages include slim ZIP archives (<20 MB) and `.delta` patches from `0.1.33 -> 0.1.34` (plus bundled repository-scoped read-only `update-token`). macOS Apple Silicon builds use the local signing identity without Apple notarization; Windows x64 remains a cross-compiled preview.
