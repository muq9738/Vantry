# Vantry 0.1.22

Reduce LAN and relay traffic without changing conversation content or end-to-end authentication.

- Send smaller T3 projection updates instead of repeatedly sending unchanged history. Fall back to authoritative snapshots for structural changes, archive transitions, or insufficient cursor space.
- Negotiate WebSocket compression for larger T3 frames.
- Compress native snapshot, workbench, and event responses inside TLS. Event responses retain a gzip dictionary and batch writes for up to approximately 8ms or 4KiB; local Unix clients retain immediate delivery.
- Multiplex native requests and persistent subscriptions over HTTP/2, including through existing linkd byte tunnels. Preserve HTTP/1.1 fallback for older peers.
- Reuse TLS sessions and bound direct TLS probes by the per-address connection timeout.
- Include the locally installed 0.1.21 updater improvements: bundled repository-scoped read-only update credentials and actionable update errors.

In fixed synthetic tests, a 41-run projection update decreased from 443,332 B to 7,115 B before WebSocket compression; 600 NDJSON events decreased from 111,982 B to 4,118 B with gzip. These fixtures are not a prediction of every production workload.

Validation covers lossless reconstruction, sparse streaming delivery, cancellation, cursor ordering, reconnect, HTTP/1.1 fallback, and multiplexing over a real relay tunnel. See [transport design and validation](../network-optimization.md).

macOS Apple Silicon packages use the existing local signing identity and are not Apple-notarized. The Windows x64 ZIP is a cross-compiled preview, without Windows hardware validation or the native remote-desktop helper. Installation remains staged until the existing application and Core can exit safely.
