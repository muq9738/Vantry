# Vantry 0.1.33

Switches Vantry back to a slim external-Pi-only distribution (well under 50 MB), adds 4-gate zero-impact verification and auto-rollback for external Pi npm upgrades with CN/direct mirror detection, and adds a full **Settings → Environments** page to manage connected and disconnected remote machines.

- **External Pi only (~18.5 MB packages, <50 MB)**: Removed the bundled standalone `pi` binary from macOS and Windows packages. Vantry discovers your system `pi` CLI (`PATH`, Homebrew, `nvm`, Windows npm/Scoop) or a pinned custom path in **Settings → Providers** while keeping the first-run model setup wizard writing directly to `~/.pi/agent` without symlinks.
- **4-gate zero-impact external Pi upgrade**: Before showing the **Upgrade Pi** (or **Install Pi**) action, Vantry checks (1) supported `1.x` SemVer stability policy, (2) local Node.js version against `engines.node` and npm-install eligibility, (3) zero active Core runs (`activeRuns == 0`), and (4) an isolated temporary `npm install --prefix` sandbox test booting `pi --mode rpc` with `builtin:codemode`, `builtin:tool-search`, `vantry_tools.ts`, and `approval.ts` (zero LLM calls, zero touch to `~/.pi/agent`). Upgrading uses the automatically detected npm registry (`registry.npmmirror.com` vs. `registry.npmjs.org`), re-verifies the live installation, and automatically rolls back to the previous version if live contract verification fails.
- **Settings → Environments**: Replaced the old single-button Connections stub with a full **Environments** Settings page (with sidebar gear shortcuts on offline/disconnected machines). Disconnected and connected paired machines can now be inspected, edited in-place (name, primary relay, fallback relays, direct LAN `host:port` addresses, re-pairing credentials), tested (`auto` / `direct` / `relay`), connected, disconnected, or removed directly in Settings.

Release packages include both slim ZIP archives and `.delta` patches from `0.1.32 -> 0.1.33` (plus bundled repository-scoped read-only `update-token`). macOS Apple Silicon builds use the local signing identity without Apple notarization; Windows x64 remains a cross-compiled preview.
