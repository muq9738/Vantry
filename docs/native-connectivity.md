# 原生远程会话与桌面共享

## 移动端局域网发现与统一配对

- **局域网发现与 Apple TLS 兼容**：移动端配对链接与已认证会话会附带物理网卡局域网 HTTPS 候选地址、归属环境 ID 以及独立的 P-256 移动端证书（`vantry.mobile`），与桌面端原生 Ed25519 证书（`vantry.remote`）解耦，以兼容 Apple `URLSession` TLS 握手校验。移动端客户端优先直连局域网地址，不可达时再回退至配置的公网 HTTPS 入口。
- **统一配对与桌面网关**：移动端完成一次电脑配对后即可同时访问会话与已开启的远程桌面。Core 通过现有移动端入口暴露 `/api/desktop/session` 与已认证的 `/api/desktop/v1/sessions/{id}` 网关，在内部校验设备凭据和共享开关，并仅转发观看端信令与媒体路由；中继凭据始终留在 Core，撤销设备、过期或断开连接时立即终止活跃媒体传输。
- **离线容错**：可选中继不可用时，局域网配对码生成、刷新与撤销仍可在本地完成，无需等待未创建的中继记录。

Vantry 回连将 `core`／`stream` 通道接到 Core，将 `t3`／`http` 接到 T3 协议适配层。

## 两项功能

| 功能 | 入口与对端 | 授权 | 承载 |
| --- | --- | --- | --- |
| 远程会话 | 主应用“设备／远程访问”；Vantry 与 T3 核心会话 | `SESSION-…` 一次性配对码；T3 使用标准配对链接／二维码；兑换后持有设备凭据 | 原生 Go、直连 TLS 或 HTTPS/WSS 中继 |
| 远程桌面 | 随包提供的远程桌面原生插件；Vantry 桌面端之间 | `DESK-…` 一次性共享码；共享端逐次确认观看与键鼠控制 | 原有 WebRTC/H.264 引擎；经用户自建中继服务的 WSS/TCP + 内置 TURN，或显式选择 LAN |

两项授权、注册令牌、配对兑换入口和关闭操作分开。会话凭据不能兑换桌面码，远程会话 API 也不能开启桌面共享、申请系统权限或读取插件凭据。撤销会话设备会关闭该设备正在读取的会话流；已交给 Core 的任务继续由 Core 持有。

联网和随包远控不要求客户端额外安装 Node/npm、GitHub CLI、SSH、Caddy 或 Nginx。执行 AI 任务仍使用执行机器已有的 Pi CLI、模型配置和凭据；这属于模型执行环境。

## 远程会话

在设备页开启“允许访问本机”，设置 Vantry 原生中继地址和会话注册令牌，然后生成会话配对码。另一台 Vantry 选择同一中继输入短码，或粘贴完整配对链接。

- **零密钥上传与内层 TLS 兑换**：主机发布到中继的引导资料仅包含公开路由、主机证书与直连地址，不包含长期设备 `secret`。使用完整 `vantry://connect#…` 链接时，客户端直接经直连或中继字节隧道建立锁定主机证书的 TLS 1.3 连接，在主机内层 TLS 通道完成 `/pairings/redeem` 并校验返回的证书、设备 ID 与路由；使用 `SESSION-…` 短码时，先从中继领取公开引导资料，再同样进入主机内层 TLS 通道领取长期设备凭据。
- **配对名额与状态一致性**：等待中的配对码与已授权设备列表分开管理；未兑换的过期/撤销码不占用 128 个已授权设备上限。关闭访问、重置配对或重新生成配对码会清理远端未兑换配对码，撤销失败时会保留待撤销 ID 以便重试。
- **有限并发直连与自动重连**：直连探测采用错峰有限并发（最多 8 个候选、并发 4、错峰 150ms），并在 `auto` 模式下于短暂直连宽限期后启动中继回退竞速；支持配置多个备用中继入口。每次新建或重连底层连接都会合并实时 mDNS 发现地址与本地配置，并在主机 IP 变化时自动刷新直连地址与 mDNS 广播。
- **数据隧道保活与证书轮换**：控制连接与每个承载业务的 WSS 字节隧道均有独立 Ping/Pong 活性检测（不依赖业务帧，不覆盖 TLS/HTTP 读超时），并在 Go HTTP/2 传输层启用 `HTTP2Config` Ping 健康探测。主机自签证书支持临期告警（到期前 30 天）、提前签发下一张证书、在已认证的 TLS 连接内自动同步给客户端，并在到期后无缝切换。
- **局域网与安全默认**：局域网发现支持多网卡 IPv4/IPv6 mDNS（含独立 TTL 缓存与关闭 Goodbye 报文）。非回环私网明文 `http://` 中继默认拒绝，仅在显式配置或 `VANTRY_ALLOW_INSECURE_LAN_RELAY=1` 时作为开发测试选项启用。

代码有效期为五分钟，只能成功兑换一次。页面显示有效期、兑换状态，并提供复制、二维码、重新生成和撤销。重新生成代码不撤销已配对设备；“撤销设备”单独撤销对应凭据并立即取消进行中的请求。关闭访问会断开访问通道；重新开启可沿用已保存设备。重置配对会更新本机身份并撤销原设备凭据。

局域网发现使用 Go 的 mDNS 实现，继续发布 `_vantry._tcp`。Vantry 配对保留证书信任与直连优先策略，直连不可用时按配置走中继。无中继的 LAN 配对通过携带公开主机证书的完整链接完成一次性兑换。

### T3 手机访问 Vantry

会话设置中的“T3 手机连接地址”必须是可达的根路径地址，例如 `https://studio.example.com:9443`。在中继 `sessions.routes` 中，把该主机名映射到设备高级设置显示的本机中继路由。手机会清除 URL 路径前缀，因此不能把旧 `/vantry-relay` 路径当作手机环境入口。

配置后生成代码，页面同时提供标准 T3 配对链接及二维码。实现包括：

- 环境描述、一次性 OAuth token exchange、持久 Bearer 设备授权、单次 WebSocket RPC ticket。
- T3 协议 2 的初始化配置、模型目录、项目／线程列表、历史投影及实时订阅。
- 创建会话、发消息、queue／steer、队列编辑／取消／转 steer、模型选择、停止、审批和提问响应。
- 断网后从 Core 的权威快照与提交游标重新同步；命令沿用 Core 的幂等命令 ID。

任务和数据库仍由原 Vantry Core 执行和保存。由其他执行环境持有的项目会保留独立项目身份；此接口拒绝把它的路径当作本机目录创建新会话，已有会话仍按 Core 保存的归属执行。

这一层不提供官方云账号发现、手机后台推送、视频远控、附件上传、终端、Git/PR、工作树创建、队列重排或模型选项编辑。未支持的操作返回错误。Core 的单次运行停止继续使用原有取消与子任务收尾语义。

### Vantry 访问 T3

设备页支持粘贴标准 T3 配对链接；输入 T3 短码时使用所选环境地址兑换。保存 T3 环境身份与设备凭据后，通过同一设备入口打开核心会话。

适配提供项目／会话投影、历史、模型、发消息、queue／steer、停止、审批与提问，以及基于 T3 权威游标的刷新。单项问题按 T3 的问题 ID 发送答案；多项问题保留为可编辑的 JSON 答案。它只声明实际提供的基础会话接口，不声明 Vantry 的插件、远控权限或跨环境编排扩展。T3 多模型选项和其他工作台扩展不自动等同于 Vantry 的功能。

## 远程桌面

远程桌面插件随 Vantry 提供，不需要先登录私有 GitHub 仓库下载 JS 入口。页面、导航、设置、启停和宿主接线均由 Go／声明式 JSON 提供；媒体仍使用独立插件模块和随包原生 helper。

在插件设置中填写自建 Vantry 桌面中继服务的 HTTPS 地址和独立桌面注册令牌。配置了中继后，页面可使用该中继；尚未配置时默认保留 LAN 可用入口，不填写虚构的公网服务器。共享默认关闭，开启意图不会跨重启保存。

共享端开启本机被控，通过系统真实的屏幕录制／辅助功能检查后生成桌面共享码。连接方输入共享码或粘贴共享链接；链接会带入中继地址。共享端看到请求设备名，明确允许本次观看与键鼠控制后才建立媒体连接。关闭共享删除该桌面会话并关闭信令与中转连接。

连接方在自己的私有数据目录保存已兑换的桌面设备凭据，以便重连；重连仍需要共享端确认，不再次向服务器兑换已消费的短码。重新生成共享码不会把已消费的代码变回可用。

跨网媒体通过客户端进程内的回环 TURN/TCP 入口，经 WSS 到自建中继服务的内置 Pion TURN。ICE 策略为 relay，统计标记 `wss-tcp`。没有启动 `ssh -W`，也没有宣称公网 UDP 已通；TCP 队头阻塞仍可能影响延迟。原硬件 H.264、原生解码与键鼠逻辑沿用现有引擎，LAN 仍可单独选择。

旧版 `vantry-rtc` SSH 信令与外部 `coturn` 方案已退役，不再作为远程桌面入口。新的桌面共享统一使用局域网直连或原生 HTTPS 中继与独立共享码。随包插件的“移除”执行停用并保留数据；原生引擎/helper 更新随应用升级。

## 独立中继程序

Vantry 源码提供独立的 `cmd/vantry-relay` 以及桌面程序的 `vantry relay` 子命令（不链接 MyGo UI、Pi 或 Core 数据库），启动示例：

```sh
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o vantry-relay ./cmd/vantry-relay
./vantry-relay init --config relay.json --listen :9443 \
  --certificate /path/to/fullchain.pem --private-key /path/to/privkey.pem --desktop
./vantry-relay serve --config relay.json
```

`init` 只创建新文件，不覆盖已有配置；文件权限为 0600。会话与桌面各有独立随机注册令牌，写在配置文件中，不打印到输出。域名路由需要补入 `sessions.routes`，示例配置结构如下；令牌使用初始化生成的值：

```json
{
  "listen": ":9443",
  "certificate": "/path/to/fullchain.pem",
  "privateKey": "/path/to/privkey.pem",
  "sessions": {
    "registrationKey": "保留 init 生成的会话令牌",
    "routes": {"studio.example.com": "设备高级设置显示的路由"}
  },
  "desktop": {"registrationKey": "保留 init 生成的桌面令牌"}
}
```

也可改为 `acmeHosts`、`acmeEmail`、`certificateDirectory`，使用内置 ACME TLS-ALPN 证书管理；需要域名验证流量能够到达相应服务的 443 入口。已有证书在新握手时重新加载，可配合原证书续期。公网监听缺少 TLS 配置时拒绝启动；本机或私网可以使用 HTTP 进行测试。

会话服务和桌面服务可分别启用。连接、主机、配对与媒体都有数量上限，支持以下安全与路由选项：

- **每路由配额与升级前置校验**：`/relay/connect` 先校验方法与 WebSocket 升级头再向主机开流；支持 `maxConnectionsPerRoute`、`maxPendingPerRoute` 隔离单路由突发流量，并在主机侧于启动转发协程前原子预留并发名额。
- **主机级凭据隔离**：除全局 `registrationKey` 外，可选配置 `hostCredentials`（为每台主机绑定独立注册令牌与允许注册/接入的路由列表，并隔离各自创建的配对记录）。
- **反向代理来源识别**：中继位于 Nginx 等反向代理后时，可通过 `trustedProxies`（IP/CIDR 白名单）从右侧解析真实客户端 IP 用于配对与建连限流；直连客户端伪造的 `X-Forwarded-For` 头会被忽略。
- **冲突探测与连接复用**：同实例主机重连遇到已有控制连接时，中继先向旧连接发送快速 Ping 探测，无响应则立即关闭半开旧连接允许接管，活跃异源主机仍返回 409。HTTP 入口按 `(route, channel)` 隔离复用连接池。
- **明文私网限制**：未配置 TLS 时默认仅允许回环监听/连接；非回环私网明文 HTTP 需在中继配置显式启用 `allowInsecurePrivateHTTP: true`。

重启中继会使尚未兑换的短码和桌面会话失效；会话主机会自动回连，已配对会话客户端仍使用主机保存的凭据。

服务管理模板位于 [deploy/relay/vantry-relay.service](../deploy/relay/vantry-relay.service)。账号、证书访问权限和可达端口按实际部署填写。

## 反向代理与过渡转发

如果自建中继位于现有 Nginx 等反向代理之后，或需要与既有 HTTP/WebSocket 入口过渡共存，可在中继配置中使用 `sessions.httpUpstreams` 按主机名与最长路径前缀进行转发；历史基于 Alma 或 FRP 的旧入口地址需要迁移到原生中继入口，已保存的本地会话与设备资料保留。

Go 测试覆盖会话直连／中继、短码用途隔离与一次性兑换、撤销、Core 读写与订阅、T3 协议 2 配对/RPC/重连、Vantry→T3 适配，以及基于双端 Pion ICE/WebRTC + 内置 TURN/WSS 隧道的信令与媒体传输测试。真实硬件编解码、macOS 系统权限与跨公网延迟仍需在目标设备上按实际环境验证。
